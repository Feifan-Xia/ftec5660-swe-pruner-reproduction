# Revised report argument and evidence map

Target 8–9 pages in each language. Build the final prose from completed evidence; placeholders remain internal until the audit passes.

1. **Research question and answer.** Lead with the measured outcome of GLM baseline versus pruning, then the measured effect of exact recovery. State eight-question/three-repeat scope. Put the paper's Streamlink GLM row beside measured rows with matched metric definitions and population differences.
2. **Why this comparison is informative.** Explain the observation → goal-conditioned skimmer → retained context → next action loop. Show how accumulating input differs from one-time source compression. Give the paper claim (54.4% lower tokens, unchanged score) as the target, not an assumed result.
3. **Design and isolated modification.** Three conditions with identical model, repository, questions, generation settings, runtime limits and independent judge. Describe observation storage, IDs, inclusive range expansion, 200-line cap and exactness accounting. Shared environment/bug fixes are common setup changes. State existing development observations and the predeclared subset, repeated at temperature zero without claiming independent random seeds.
4. **Main evidence.** All 24 cells per condition; availability, quality dimensions, cumulative tokens, source retention, authors' round count, API requests and actual provider cost. Give per-repeat mean/SD and question-cluster paired intervals. Retain unsuccessful original attempts and explain any recovery policy.
5. **Interpretation.** Per-question differences; pruning activation frequency; number of later requests that reuse earlier contexts; large outputs and peak prompt sizes; repeated exact commands; source-token savings versus cumulative usage. Acknowledge the difference between association and intervention. Select examples by largest/smallest paired token change, and inspect both, including any low-quality or failed case.
6. **Modification evidence at two levels.** Autonomous SWE-QA shows actual tool uptake and end-to-end trade-offs. The separate predeclared goal-shift probe tests whether missing stored evidence is recoverable: eight code fixtures × three conditions × three runs, exact literal match, no LLM judge. Include all fixtures, including the one whose target survives pruning. State the deliberately constrained stored-observation setting and its relevance to XJ13; autonomous repository agents also have rereading options.
7. **Reproduction blockers and limits.** Explain final-answer export repair; original 60-second pruning failures on 8GB GPU; query-tiled SDPA with all keys/values, numeric checks and memory/time measurements; one padding-sensitive token at threshold 0.5; model serving routes and judge deployment differences; subset coverage and shared cache effects; read-only shell isolation. Keep diary concise and tie each fix to measured validity.
8. **Conclusions, instructions and references.** State exactly which behavior was reproduced, whether the paper's quantitative trade-off appeared in this subset, and when recovery helped. Link pinned code, data provenance, runtime snapshot, raw traces and rerun commands. Demo recording/publication remain user steps.
